DocIntel – Multimodal Document Intelligence (HACKNEX '26 · HNX26PSI01)

Ask questions over mixed documents (text, tables, charts, scanned pages, images) and get an answer that cites the document, page and section it came from. Answers that cannot be tied to a verified page are withheld.

What it does
Ingestion: PDFs and image scans. PyMuPDF extracts text and tables and renders every page as an image.
Visual content is analysed as visual: charts, scans and image pages are transcribed/described by a vision model at index time, and the top pages are sent to the model as images at question time (max 3).
Hybrid retrieval: sentence embeddings + FAISS (meaning) and BM25 (exact words/numbers), fused with Reciprocal Rank Fusion, aggregated to pages. Works across multiple documents.
Answering: the vision-language model returns JSON (answer, calculation, reasons, citations).
Verification: citations to pages that were not retrieved are dropped; a second check asks whether each cited page supports the claim. No verified citation = no answer.
Math: the model supplies an arithmetic expression; the server evaluates it with a safe AST evaluator.

Setup

Requires Python 3.10+ and an Anthropic API key.

python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export ANTHROPIC_API_KEY=your_key                      # Windows: set ANTHROPIC_API_KEY=your_key
uvicorn server:app --port 8000

Open http://localhost:8000, click Load sample documents (generates a report with text + table + chart and a scanned audit page), then ask e.g. "Compare production efficiency between Q2 and Q4, identify the three biggest reasons, and show the proof." The first start downloads the embedding model (~130 MB). Optional env vars: ANSWER_MODEL, EMBED_MODEL.

Without an API key, indexing and /search still work, but /ask and chart/scan captioning need the key. To try the project with no setup at all, open demo/demo_offline_sample.html in a browser.

API

POST /ingest (file) · POST /sample · GET /library · POST /search {question} · POST /ask {question} · GET /page/{doc}/{n}

External tools, models and data
Claude (Anthropic API) – vision-language answering, page captioning and citation checking (default claude-sonnet-5-5)
BAAI/bge-small-en-v1.5 via sentence-transformers – embeddings
FAISS (faiss-cpu), rank-bm25, PyMuPDF, FastAPI/Uvicorn
Sample documents are synthetic and generated by the code; no external datasets are used.
Known limitations (honest status)
Backend code has been syntax-checked but not run end to end; expect small fixes on first run.
Index is in memory (lost on restart). No OCR/denoising step for badly damaged scans.
Each answer makes several model calls (answer + one check per citation), so it is slower and costs more.
No "latest report wins" logic yet for conflicting figures across years (planned: per-chunk period metadata and conflict resolution).
Accuracy has not been benchmarked on a labelled question set.
